# HSE Tech — پلتفرم آموزشی ایمنی، بهداشت و محیط زیست

پلتفرم آموزشی B2C برای برگزاری دوره‌های تخصصی HSE: فروش دوره، برگزاری کلاس آنلاین
و آفلاین، آزمون، صدور گواهی و استعلام عمومی گواهی.

| موضوع | فناوری |
|---|---|
| زبان | Python 3.12 |
| فریم‌ورک | Django 5.2 LTS |
| قالب | Django Templates + Bootstrap 5 (محلی) |
| دیتابیس توسعه | SQLite |
| دیتابیس Production | PostgreSQL |
| سرور Production | Ubuntu + Gunicorn + Nginx |

> **وضعیت فعلی: فاز ۵ — احراز هویت (تطبیق کد ملی و شماره موبایل).**
> نقشه راه کامل: [`docs/roadmap.md`](docs/roadmap.md) · معماری و دیتابیس: [`docs/architecture.md`](docs/architecture.md)

## راه‌اندازی پروژه روی سیستم شما

پیش‌نیاز: **Python 3.12** و **Git** نصب باشند. برای بررسی:

```bash
python --version
git --version
```

### ۱. دریافت پروژه

```bash
git clone <آدرس-مخزن>
cd HSE-academy
```

### ۲. ساخت محیط مجازی (Virtual Environment)

محیط مجازی یک پوشه جداست که کتابخانه‌های این پروژه فقط داخل آن نصب می‌شوند و با
سایر پروژه‌های سیستم شما تداخل پیدا نمی‌کنند.

**ویندوز:**

```bat
python -m venv .venv
.venv\Scripts\activate
```

**لینوکس / مک:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

بعد از فعال شدن، ابتدای خط ترمینال عبارت `(.venv)` را می‌بینید. **تا وقتی این را
نمی‌بینید، دستورهای بعدی را اجرا نکنید.**

### ۳. نصب کتابخانه‌ها

```bash
pip install --upgrade pip
pip install -r requirements.txt
```

### ۴. ساخت فایل تنظیمات `.env`

**ویندوز:**

```bat
copy .env.example .env
```

**لینوکس / مک:**

```bash
cp .env.example .env
```

فایل `.env` رمزها و کلیدهای شماست و **هرگز داخل گیت ذخیره نمی‌شود**. برای شروعِ
توسعه، مقادیر پیش‌فرض کافی است و نیازی به تغییر ندارند.

### ۵. ساخت جدول‌های دیتابیس

```bash
python manage.py migrate
```

### ۶. ساخت کاربر مدیر

نام کاربری سایت **شماره موبایل** است، نه username.

```bash
python manage.py createsuperuser
```

### ۷. اجرای سرور

```bash
python manage.py runserver
```

حالا در مرورگر باز کنید:

- سایت: <http://127.0.0.1:8000/>
- پنل مدیریت: <http://127.0.0.1:8000/admin/>
- بررسی سلامت: <http://127.0.0.1:8000/health/>

برای خاموش کردن سرور، در ترمینال `Ctrl + C` بزنید.

> **هر بار که پنجره ترمینال را می‌بندید و دوباره باز می‌کنید**، قبل از هر کاری
> این دو دستور را اجرا کنید — وگرنه پایتون پروژه را پیدا نمی‌کند:
>
> ```bash
> cd مسیر/پروژه/HSE-academy
> .venv\Scripts\activate        # ویندوز
> source .venv/bin/activate      # لینوکس و مک
> ```

## دستورهای کمکی محیط توسعه

### ساخت داده نمونه

تا صفحه اصلی پر و واقعی به نظر برسد و بتوانید طراحی را ببینید:

```bash
python manage.py seed_demo
```

برای پاک کردن داده نمونه قبلی و ساخت مجدد:

```bash
python manage.py seed_demo --reset
```

### ساخت گروه‌های نقش

نقش‌های سایت (مدیر، مدرس، مدیر محتوا، پشتیبانی، مالی، دانشجو) و دسترسی هر کدام:

```bash
python manage.py setup_groups
```

اجرای چندباره‌اش بی‌خطر است. برای دادن نقش به کاربر: پنل مدیریت ← کاربران ←
انتخاب کاربر ← بخش «دسترسی‌ها» ← افزودن گروه.

### ساخت یا بازنشانی حساب مدیر

دستور استاندارد `createsuperuser` رمز را نامرئی می‌گیرد و اگر اشتباه تایپ شود
راهی برای فهمیدنش نیست. این دستور رمز را روی صفحه نشان می‌دهد:

```bash
python manage.py make_admin 09121234567 hse12345
```

دیدن حساب‌های موجود:

```bash
python manage.py make_admin --list
```

> این دستور فقط در محیط توسعه کار می‌کند. روی سرور از `createsuperuser` و
> `changepassword` استفاده کنید.

## پنل پیامک

در محیط توسعه نیازی به پنل پیامک نیست. `USE_MOCK_SMS=True` است و کد تأیید
به‌جای ارسال، **در ترمینال چاپ می‌شود**:

```
============================================================
  پیامک آزمایشی (ارسال واقعی انجام نشد)
  گیرنده : 09121234567
  متن    : 483927
============================================================
```

### وقتی پنل واقعی خریدید

در فایل `.env`:

```env
USE_MOCK_SMS=False
SMS_PROVIDER=kavenegar
SMS_API_KEY=کلید-پنل-شما
SMS_SENDER_NUMBER=شماره-خط-شما
SMS_OTP_TEMPLATE=نام-الگو        # اختیاری، ارسال با الگو ارزان‌تر است
```

هیچ کد دیگری تغییر نمی‌کند. اگر پنل دیگری خریدید، از روی کلاس
`KavenegarSmsProvider` در `apps/accounts/services/sms.py` یکی مشابه بسازید
و نامش را به دیکشنری `PROVIDERS` اضافه کنید.

> در محیط توسعه حتی اگر کلید پنل واقعی در `.env` باشد، باز هم نسخه آزمایشی
> استفاده می‌شود — تا به اشتباه از اعتبار پنل خرج نشود.

### تنظیمات کد یکبارمصرف

| متغیر | پیش‌فرض | معنی |
|---|---|---|
| `OTP_EXPIRY_SECONDS` | ۱۲۰ | اعتبار کد (ثانیه) |
| `OTP_MAX_ATTEMPTS` | ۵ | حداکثر تلاش برای هر کد |
| `OTP_RESEND_COOLDOWN_SECONDS` | ۹۰ | فاصله لازم بین دو ارسال |
| `OTP_MAX_SENDS_PER_HOUR` | ۵ | سقف درخواست کد در ساعت |

## سرویس احراز هویت (تطبیق کد ملی و موبایل)

در محیط توسعه نیازی به خرید سرویس نیست. رفتار شبیه‌سازی با
`MOCK_IDENTITY_RESULT` در `.env` کنترل می‌شود:

| مقدار | نتیجه |
|---|---|
| `matched` | همیشه تطبیق دارد (پیش‌فرض) |
| `not_matched` | همیشه تطبیق ندارد — برای تست پیام خطا |
| `failed` | همیشه خطای سرویس — برای تست قطعی سرویس |
| `by_national_code` | ختم به ۰۰ تطبیق ندارد، ختم به ۹۹ خطا |

> کد ملی باید رقم کنترلی درست داشته باشد وگرنه فرم قبل از تماس با سرویس
> ردش می‌کند. نمونه کد معتبر برای تست: `0499370899`

### وقتی سرویس واقعی را خریدید

```env
USE_MOCK_IDENTITY=False
IDENTITY_PROVIDER=shahkar
IDENTITY_API_BASE_URL=آدرس-سرویس
IDENTITY_API_KEY=کلید-شما
```

نام فیلدهای درخواست و پاسخ را در `apps/accounts/services/identity.py`
مطابق مستندات سرویسی که خریدید تنظیم کنید. بقیه پروژه دست‌نخورده می‌ماند.

### اجباری بودن احراز هویت

```env
IDENTITY_REQUIRED_FOR_REGISTRATION=True   # پیش‌فرض
```

با `True` بدون تطبیق هویت حساب ساخته نمی‌شود. با `False` کاربر ثبت‌نام
می‌کند اما تا تکمیل احراز هویت، گواهی برایش صادر نخواهد شد.

## نکات مهم

**اسلایدر صفحه اصلی:** تصاویر از پنل مدیریت ← «اسلایدهای صفحه اصلی» آپلود می‌شوند.
روی اسلاید هیچ متنی نوشته نمی‌شود، پس کل پیام باید داخل خود تصویر باشد.
اندازه پیشنهادی ۱۹۲۰×۶۵۰ پیکسل. چرخش خودکار هر ۵ ثانیه است و کاربر با دکمه‌های
کناری، نقطه‌های پایین یا کشیدن انگشت هم می‌تواند جابه‌جا شود.

**تاریخ‌ها شمسی هستند.** تبدیل میلادی به شمسی بدون کتابخانه خارجی و در فایل
`apps/core/jalali.py` انجام می‌شود؛ صحت آن با تست بررسی شده است.

**فایل `.env` را در گیت قرار ندهید.** این فایل در `.gitignore` هست. اگر کلیدی به
اشتباه commit شد، باید آن کلید را باطل و کلید جدید بسازید.

**وابستگی به اینترنت خارجی:** تمام فایل‌های CSS، JS، فونت و آیکون به‌صورت محلی در
پوشه `static/` نگهداری می‌شوند. از Google Fonts یا CDN خارجی استفاده نمی‌کنیم تا
سایت در زمان اختلال اینترنت بین‌الملل هم کامل بالا بیاید.

**سرویس‌های خارجی در حالت Mock:** پیامک، استعلام هویت و پرداخت در محیط توسعه
شبیه‌سازی شده‌اند (`USE_MOCK_SMS`، `USE_MOCK_IDENTITY`، `USE_MOCK_PAYMENT` در فایل
`.env`). یعنی می‌توانید کل جریان ثبت‌نام تا خرید را بدون خرید هیچ سرویسی تست کنید.

## تنظیم VS Code

فایل `.vscode/settings.json` از قبل آماده است. فقط یک نکته برای **ویندوز**: مسیر
مفسر پایتون را به این تغییر دهید:

```json
"python.defaultInterpreterPath": "${workspaceFolder}\\.venv\\Scripts\\python.exe"
```

یا ساده‌تر: `Ctrl+Shift+P` → `Python: Select Interpreter` → گزینه‌ای که داخل آن
`.venv` نوشته شده را انتخاب کنید.
